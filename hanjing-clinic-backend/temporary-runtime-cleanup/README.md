# 临时运行数据清理模块

用途：超级管理员在数据库工具中选择业务，预览关联删除范围后执行清理。不是正式退款、库存退货或账户注销功能。

## 代码边界与拆除
1. 删除 `hanjing-clinic-backend/temporary-runtime-cleanup/` 整个目录。
2. 在 `hanjing-clinic-backend/routes/admin.js` 删除 `installTemporaryRuntimeCleanup` 的 import 和注册调用，共两处。
3. 删除 `hanjing-clinic-管理后台源码-20260607/src/components/temporary-runtime-cleanup/` 整个目录。
4. 在 `src/views/settings/database-tools.vue` 删除 `TemporaryRuntimeCleanup` 的 import 和组件标签，共两处。
5. 可删除 `tests/admin/temporary-runtime-cleanup.integration.mjs` 和 `tests/admin/temporary-runtime-cleanup.browser.mjs`；Markdown 记录建议保留作为历史，同时移除入口索引或注明功能已拆除。
6. 重启后端、重新构建前端；确认三个 `/api/admin/database/temporary-cleanup` 接口不再可访问。

没有新增永久数据库表、迁移、角色权限项或系统设置。临时表仅存在于单次数据库连接，连接结束自动消失。审计日志保留操作记录，不应清除。

## 运行边界
- 只接受固定业务组，不接受客户端表名或 SQL；仅超级管理员。即使普通账号持有数据库查看/同步权限也不能使用。
- 预览返回实际记录数和受影响表，随机确认凭证绑定账号、选择项及数据主键集合，5分钟有效、仅用一次。输入“确认清理”才能提交。
- 执行重新计算范围并比对凭证；数据变化时要求重新预览。使用 InnoDB、串行化事务和行范围锁，失败回滚。不使用 TRUNCATE，不关闭外键约束，不重置自增或预约编号流水。
- 通过外键追踪子记录，补充订单 appointment_id、收银 JSON 患者、改约历史、交付生产关系等没有外键的关联。未知的受保护表依赖会阻止清理。
- 保留角色、权限、成员、微信通知配置和日志、系统设置、操作审计、门店、医生、患者登录账号。清理患者时解除本人档案关联，并清理账号的积分、会员、优惠券及业务通知记录。不会删除服务器附件文件。
- 删除预约仅影响关联订单；清理患者还包括收银上下文中的患者订单及没有具体患者信息的该账号商城订单。不会删除其他账号的无关订单。
- 独立清理评估保留预约，仅解除评估引用。未选择商品清理时保留商品库存；按剩余订单重算涉及商品销量、排班占用和相关账号会员等级（保留人工保护等级）。
- 同一推广员的提现不能精确拆分到某一订单：涉及佣金删除时，将该推广员完整佣金和提现流水一起纳入预览，保留其账号、二维码和绑定关系。请核对清单后决定是否执行。
- 实际支付和退款在外部渠道仍然存在，本功能只清理当前数据库，不发起退款或撤销支付。开发验证仅在自动创建的隔离库执行；未清理本地真实业务或正式环境。

## 验证
`tests/admin/temporary-runtime-cleanup.integration.mjs` 创建隔离数据库，执行真实接口与清理事务，最后删除隔离库。需通过环境变量提供 TEST_DB_PASSWORD，不将凭据写入文件。

- 商品管理清理全部商品；商品分类按 products.category = product_categories.code 关联商品。包含这些商品的整笔订单及支付退款、交付和佣金流水纳入预览，不保留残缺订单。诊疗设备仅解除商品引用。
- 科普文章包含官方文章及用户帖子；内容分类按文章 tags 中的分类名称匹配，带出文章及互动记录。不匹配分类的文章保留。
- 现有数据库初始化会补建 device/accessory/service 三个默认商品分类；清理不会改写初始化逻辑，重启服务后这些默认分类会按既有规则重新生成。
