# 按部署代码同步数据库字段

入口：管理后台 → 数据库工具 → 预览并同步结构。

## 结构依据

同步会在同一 MySQL 服务上创建一个随机命名的隔离参考库，用当前部署代码的 `initDB()` 及其引用的迁移生成最终结构。旧迁移存在前向表引用，因此参考库执行两轮初始化；第二轮非“对象已存在/待删除对象不存在”的 DDL 错误会阻止同步。参考库随任务清理。

业务字段是否保留以这份最终结构为准，不按业务代码中某个字符串是否出现来猜测。废弃字段应从建表及所有增量迁移定义中移除；只从接口、页面或最初的 CREATE 中删除、却仍被 ADD COLUMN 迁移添加的字段仍是当前代码定义的字段。

## 执行流程

1. 预览新增表、增删改字段、字段顺序和约束差异。预览不修改业务库结构。
2. 在维护窗口停止业务写入，确认差异。后端重新生成目标结构并验证预览指纹，代码或现有结构改变后必须重新预览。
3. 在独立的 `hj_schema_backup_*` 数据库中备份受影响的既有表；`_schema_sync_metadata` 保存原表字段、索引、外键、CHECK 定义及来源库。备份失败不开始结构变更。
4. 按依赖顺序处理外键、字段及索引，再恢复外键。字段删除会删除该字段的数据；备份不属于业务表，不会造成业务表保留废弃字段。
5. 重新读取结构。只有代码定义表的字段、索引语义和约束核验一致才返回成功。MySQL 自动生成的等价索引名称不作为差异；重复的多余索引仍会移除。

普通服务启动不调用此破坏性清理流程，继续执行既有初始化及迁移；部署后需要通过上述入口确认清理。

## 边界与恢复

- 只处理当前代码定义的表，不自动删除整张未纳管表；预览会列出未纳管表。
- 引擎、字符集或表选项不一致、跨库外键、未纳管表引用待修改表、视图或触发器等无法安全自动判断的情况，会停止并说明原因。
- 同步账户需有参考库/备份库创建、删除参考库、读取、插入和目标表 DDL 权限；缺少权限直接报错。
- 命名锁防止两个同步同时执行，不代替业务维护停写；备份和 DDL 期间必须保持维护状态。
- MySQL DDL 不支持整批事务回滚。类型收窄、重复唯一值或外键数据不兼容等错误会停止执行，可能已有部分 DDL 生效；错误包含已执行条数和备份库名，不会假报成功。
- 恢复时先保持停写，依据备份表及 `_schema_sync_metadata` 核对并恢复受影响表和原约束。`CREATE TABLE LIKE` 本身不复制外键，因此不能只复制备份表就宣称完整恢复。备份库由管理员验证并决定保留周期，程序不会自动删除业务恢复备份。
- 前端请求超时不意味着数据库操作已取消；保持维护状态，等待任务结束并重新预览核对，不能直接恢复业务。
