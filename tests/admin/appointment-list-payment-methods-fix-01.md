# 预约列表挂号收费付款方式修复

- 日期：2026-10-23
- 状态：待回归
- 范围：运营后台「预约管理」列表的「挂号收银 / 收银结算」共用弹窗

## 目标

- 付款方式仅保留「现金支付」和「小程序支付」。
- 默认选择现金支付。
- 现金支付提交前再次确认已实际线下收款，确认后完成订单收款登记。
- 小程序支付只生成待支付订单，通知用户前往小程序预约详情完成支付。
- 不修改商城、处方、检查等其他收款入口。

## 验证记录

- `npm.cmd run typecheck`：通过。
- `npm.cmd run build`：通过，共转换 6631 个模块；仅存在项目原有的大分块提示。
- 静态残留检查：预约列表页面已无 `wechat_native`、`wechat_micropay`、微信收款码、顾客付款码、扫码轮询状态及对应导入。
- 本地运行页检查：`http://127.0.0.1:3000/appointment` 返回 HTTP 200，开发服务已加载当前代码。

## 实现结果

- 「挂号收银」与「收银结算」共用弹窗默认选择现金支付。
- 支付区只显示现金支付、小程序支付，并补充两种方式各自的结果说明。
- 现金提交前要求确认已经实际收到现金；成功后继续保留现有收据和完成结算流程。
- 小程序支付生成待支付订单后关闭弹窗、刷新预约列表；后端既有预约订单通知链路会发送预约详情入口。
- 删除本页面原微信收款码、扫顾客付款码、二维码展示与支付状态轮询逻辑，未改动其他业务页面的付款能力。
