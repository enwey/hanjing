## 改动点

- BIND-03：mp-weixin-rewrite/api/modules/distribution-api.js，按登录令牌和邀请码共享进行中的 Promise，覆盖 app 与 session 两个入口；成功/失败均释放，不同令牌不共用请求。
- BIND-04：hanjing-clinic-backend/routes/admin.js，绑定仅接受 active/pending 推广身份，只有 pending 可首次激活；停用身份被拒绝。
- BIND-05：同一路由在事务中锁定患者、推广身份、被邀请用户与逐级祖先用户，沿一级父链拒绝重复祖先及回到被邀请人。用户行锁协议与小程序绑定入口一致。
- BIND-06：显式改绑时只替换当前患者关联用户的一、二级关系：一级使用新推广员，二级使用其当前一级上级；新推广员无上级则不保留旧二级关系。不改写被绑定用户的其他下级，也不追溯佣金订单。
- BIND-07：身份读取、关系替换及 pending 激活使用同一事务连接；其中任何写入失败会回滚，成功提交后才记录审计与返回成功。现有审计日志函数内部处理日志写入异常。
- 患者未关联小程序账号时明确拒绝，避免无有效用户 ID 的关系写入。
