# 新建预约与挂号收银固定项目修复

- 日期：2026-10-23
- 状态：待回归
- 范围：运营后台新建预约收银、预约列表待支付预约的挂号收银

## 目标

- 不允许添加收费项目。
- 不显示配送/交付方式。
- 所有项目和商品数量固定为 1，不允许编辑。
- 不允许删除项目。
- 预约列表挂号收银窗口与新建预约一致，仅提供现金支付和小程序支付，不显示扫码支付及履约技师。
- 两个入口复用同一个收银面板组件，避免后续样式或字段分别修改后再次产生差异。
- 列表中的诊后「收银结算」保持原有可追加项目及交付能力。

## 验证记录

- `npm.cmd run typecheck`：通过。
- `npm.cmd run build`：通过，共转换 6635 个模块；产物包含独立的 `RegistrationCheckoutPanel` 共享组件分块，仅存在项目原有的大分块提示。
- 新建预约静态检查：收费明细加载和提交时均将数量归一化为 1；模板无添加项目、配送/交付选择、数量输入框和删除按钮。
- 挂号收银静态检查：以 `pending_payment` 状态识别受限场景；添加、删除方法设有逻辑保护，模板隐藏添加、删除、配送及地址表单，提交时再次强制数量为 1、现场交付且无配送地址。
- 诊后收银结算检查：仅 `pending_payment` 进入受限模式，`completed` 预约仍显示添加、删除、数量编辑与配送/交付方式。
- 挂号收银窗口一致性检查：扫码支付和履约技师仅在非挂号收银场景渲染；挂号收银只显示现金、小程序支付，并在提交层拒绝异常的 `wechat_native` 值。
- 组件复用检查：新建预约和列表挂号收银均渲染 `RegistrationCheckoutPanel.vue`；原新建预约内重复的收银模板已删除，两个入口共享项目表格、金额汇总、支付选项、说明和按钮布局。
- 本地运行页检查：`/appointment/create` 与 `/appointment` 均返回 HTTP 200。
- `git diff --check`：通过；仅提示工作区现有 LF/CRLF 转换告警。
- 视觉验证：受阻。Computer Use 初始化报错 `failed to write kernel assets: 系统找不到指定的路径。 (os error 3)`，未将未执行的浏览器目视检查标记为通过。

## 实现结果

- 新建预约的收费项目只能查看，数量固定显示为 1，且提交数据强制为 1。
- 挂号收银不再显示添加项目、删除、配送/交付方式及其附属地址表单，数量固定为 1。
- 预约列表挂号收银与新建预约一致：默认现金，只提供现金和小程序支付，不显示扫码支付及履约技师选择。
- 新建预约与列表挂号收银已共用 `RegistrationCheckoutPanel.vue`，不再依靠两份相似模板分别维护。
- 诊后「收银结算」保持原业务能力，避免影响诊疗后追加收费项目和实物交付。
