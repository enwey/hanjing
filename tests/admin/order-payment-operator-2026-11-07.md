# 订单收款与退款操作人

状态：待回归（实现及开发专项自测完成，未开展独立回归）

## 实现范围

- 商城订单与历史预约订单共用订单退款链路；新增可信后台账号 ID、姓名快照、操作时间，忽略客户端伪造字段。
- 现金、银行转账确认收款时保存收款人；现场微信扫码/付款码保存首次收款发起人，回调不改写。生成收款码但尚未到账，不展示为已收款。
- 患者微信自助支付标明自动确认，不记为某个工作人员收款；零元订单标明无需支付。
- 线下实际退款登记及微信退款审核通过时保存退款操作人；微信超时仍保留发起人，查询结果、重复回调及重复登记不覆盖。
- 后台订单详情增加“收款与退款记录”，显示收款人、收款时间、退款操作人、退款操作时间、退款状态和到账时间。
- 旧版线下退款凭证已有 actor_id / registered_at 的，详情按原记录显示账号和登记时间；无法确定的历史操作人显示“历史未记录”，不猜测补填。
- 未调整收费、退款金额、预约状态规则或原有退款权限；不改变历史预约按原订单退款的路径。

## 数据字段

全部位于 `orders`，允许 NULL，不以外键关联强制删除历史记录：

| 字段 | 类型 | 说明 |
| --- | --- | --- |
| collected_by_admin_id | BIGINT UNSIGNED | 收款/现场微信收款发起账号 |
| collected_by_name | VARCHAR(100) | 当时账号姓名快照 |
| collection_source | VARCHAR(24) | admin / patient_wechat / wechat_native / wechat_micropay / no_payment |
| refunded_by_admin_id | BIGINT UNSIGNED | 实际登记退款或提交微信退款的账号 |
| refunded_by_name | VARCHAR(100) | 退款操作时姓名快照 |
| refund_requested_at | DATETIME | 登记/提交退款时间；到账时间仍使用 refund_at |

## 开发自测

隔离 MySQL 库，业务前提通过实际 HTTP API 创建；历史预约使用现存兼容付款函数产生订单。仅账号权限引导使用 SQL，未使用 SQL 修改业务状态。全程拒绝公网请求，微信退款通过模拟 provider、扫码支付使用签名的模拟渠道响应，不触及真实资金。临时库已清理。
