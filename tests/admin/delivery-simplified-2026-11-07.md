# 简化交付流程与售后衔接

状态：待回归（实现及开发专项自测完成，未进行独立回归）

## 按用户要求实现

1. 汇总送厂后立即生成清单、锁定资料快照并下载真正的 `.xlsx` Excel 文件，可重新下载；不再录入寄出、工厂签收和制作进度。
2. 新批次 `exported`，明细和交付状态 `awaiting_return`。界面统一“待回货”；旧批次数据保留，旧在途状态可直接回货确认，不伪造历史寄出时间。
3. 患者交付列表、批次详情支持多选确认回货，也可单个确认；无需填写设备编号、入库位置。后台保存确认人和时间，重复确认不重复登记；任一选择无权限、付款异常或环节不符时整批回滚。
4. “完成试戴”改为“确认试戴”，回货后可直接操作，通知试戴仍可选。填写订单设备、初始下颌前移量、治疗启动日期、下次微调复查日期及备注。
5. 确认时在同一事务内绑定患者设备、创建/更新治疗记录、保存参数和下次复查日期、创建关联的随访及售后微调复查工单；重复提交不会重复生成。
6. 售后显示“下次复查日期”，自动工单分配给该交付技师，关联患者设备和随访任务；售后转派同步随访负责人，解决/关闭结束对应随访安排。
7. 角色权限目录不再显示送厂寄出/制作进度操作，回货接口继续严格验证 `fulfillment:receipt`，未放宽账号权限。

## 历史实现核对

核对 Git `21d6765` 的 `fulfillment-treatment.js`：原有初始前移量、治疗启动日期、下次微调日期、患者设备绑定，并建立“阻鼾器物理微调复查”随访任务。原来没有自动售后工单。本次保留原设备/治疗关联方式，将同一复查任务关联到售后；病历归属校验、支付状态校验仍保留。

新增 `after_sales_tickets.next_service_date DATE` 与 `follow_up_task_id BIGINT UNSIGNED`（均可空，旧工单不补造计划）。售后API按日期字符串返回，避免UTC序列化造成日期偏移。
