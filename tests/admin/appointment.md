## 【逐项测试发现】

### ADMIN-APPT-01：搜索框宣称支持预约单号，但精确预约单号搜索返回空结果

- 状态：回归通过
- 潜在缺陷：后端搜索条件只覆盖患者姓名、手机号和医生姓名，没有预约单号字段。
- 现象：列表首条预约单号为 `AP202606140001`，使用该完整单号搜索返回 200，但总数与列表均为 0。
- 预期：占位提示“搜索患者/预约单号”所列的完整预约单号应能精确找到对应记录。
- 实际结果：已有记录无法通过其预约单号检索。
- 风险等级：中。
- 复现步骤：打开预约管理 → 复制任一现有预约单号 → 输入搜索框 → 观察结果为空。
- 观察项：患者姓名、手机号和医生姓名路径未发现同类问题；模糊单号同样不在查询条件内。

### ADMIN-APPT-02：负页码或负分页大小触发服务端 500

- 状态：回归通过
- 潜在缺陷：分页参数经 `parseInt` 后未校验正整数范围，直接拼入 `LIMIT/OFFSET`。
- 现象：`page=-1&pageSize=30` 和 `page=1&pageSize=-1` 均返回 500“获取预约列表失败”。
- 预期：非法分页参数应返回明确的 400，或安全回退到受控默认值，不应进入数据库语法错误路径。
- 实际结果：外部可控参数稳定触发 500。
- 风险等级：中。
- 复现步骤：携带有效管理员 Token 请求上述两个 URL → 查看响应状态。
- 观察项：超大页码、超大 pageSize、非数字和小数尚未逐一压测。

### ADMIN-APPT-03：损坏或过期的持久化筛选值无法恢复

- 状态：回归通过
- 潜在缺陷：状态标签、门店和医生从 localStorage 读取后没有合法值校验。
- 现象：写入 `corrupt`、`已删除门店`、`已删除医生` 后刷新，没有状态标签选中，筛选值原样保留，列表显示空数据且没有异常提示。
- 预期：未知状态和已经不存在的门店/医生应回退到“全部”合法状态，并明确加载真实列表。
- 实际结果：页面形成无选中标签的幽灵筛选状态，用户无法区分无数据和筛选失效。
- 风险等级：中。
- 复现步骤：设置三个 `appt_list_*` 缓存值 → 刷新 `/appointment` → 查看标签与列表。
- 观察项：后端对 `status=corrupt` 仍返回 200 空列表，加重了前端误判。

### ADMIN-APPT-04：预约列表请求失败时页面没有可见错误状态

- 状态：回归通过
- 潜在缺陷：异常分支仅写控制台，不设置错误提示，也没有明确区分旧数据、空数据和请求失败。
- 现象：浏览器侧阻断 `/api/admin/appointments` 后切换标签，页面没有 alert，也没有“加载失败”文本。
- 预期：请求失败应给出明确、可感知且可重试的错误状态，不应表现成正常空数据或保留旧数据。
- 实际结果：用户只能看到空表或此前内容，无法知道数据已失去时效性。
- 风险等级：中。
- 复现步骤：打开预约管理 → 阻断预约列表接口 → 切换状态标签 → 查看页面反馈。
- 观察项：快速切换多个筛选时也缺少请求序号隔离，旧响应覆盖新筛选结果存在风险线索。

### ADMIN-APPT-05：375px 下 1164px 表格被裁切且没有可用横向滚动区域

- 状态：回归通过
- 潜在缺陷：表格没有独立滚动容器，父面板会隐藏溢出内容。
- 现象：375px 视口中面板宽 272px、表格宽 1164px，但文档宽仍为 375px、内容滚动宽仅 296px。
- 预期：窄屏下表格应提供可操作的局部横向滚动，或采用适配布局，确保状态和操作列可达。
- 实际结果：右侧大部分列及操作按钮无法通过页面滚动访问。
- 风险等级：中。
- 复现步骤：登录并打开预约管理 → 将视口调整为 375×812 → 尝试访问表格右侧状态与操作列。
- 观察项：真实移动设备、触摸滚动、平板宽度尚未验收。

### ADMIN-APPT-06：修改既有预约的 POST 子资源被错误归类为新增权限

- 状态：回归通过
- 潜在缺陷：权限映射按 POST 一律推导为 `add`，没有区分集合创建和既有资源子操作。
- 现象：`POST /appointments/123/pre-exam`、`POST /appointments/123/postpone` 均要求 `appointment:add`；同一预约的 PUT 才要求 `appointment:edit`。
- 预期：修改既有预约的预检、延期等操作应受编辑类权限约束，不能仅凭新增权限进入处理链路。
- 实际结果：“可新增、不可编辑”的角色存在修改既有预约的授权边界风险。
- 风险等级：高。
- 复现步骤：调用 `requiredAdminPermissions` 检查上述路由 → 返回 `appointment:add`；本轮未对真实预约执行越权写入。
- 观察项：保存/完成诊疗映射到 `medical_record:add`，其他 POST 子资源也需逐项审核。
