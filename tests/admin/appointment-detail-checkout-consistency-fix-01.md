# 预约详情收银规则一致性修复

- 日期：2026-10-23
- 状态：待回归
- 范围：运营后台预约详情的挂号收银与收银结算

## 目标

- 详情页挂号收银与列表页一致：禁止添加、删除及配送，数量固定为 1。
- 详情页诊后收银结算与列表页一致：保留追加项目、数量调整和配送能力。
- 支付数据提交时同步执行相同约束，不能只依赖界面隐藏。
- 支付方式与列表页一致：默认现金，仅保留现金、小程序和扫码支付，并支持打印右下角二维码支付单。

## 验证记录

- `npm.cmd run typecheck`：通过。
- `npm.cmd run build`：通过，共转换 6632 个模块；仅存在项目原有的大分块提示。
- 静态检查：以详情数据中的 `pending_payment` 状态识别挂号收银；项目加载和提交均将数量强制为 1，添加与删除方法设有逻辑保护。
- 模板检查：挂号收银隐藏操作列、删除按钮、添加项目、配送/交付方式及附属地址表单；固定数量显示为 1。
- 诊后收银结算检查：`completed` 状态不会进入挂号限制，仍保留添加、删除、数量编辑和交付设置。
- 支付方式检查：类型限定为 `cash | wechat | wechat_native`，默认现金；付款码状态、输入框、提交分支及 `submitMicropay` 导入均已移除。
- 小程序支付检查：订单创建后关闭收银弹窗、刷新预约详情，并提示用户前往小程序预约详情支付。
- 扫码支付检查：复用微信 Native 支付接口和真实状态轮询；支付单显示订单、项目、金额及右下角二维码，打印模式仅显示当前凭证。
- 本地运行页检查：`/appointment/detail/1` 返回 HTTP 200。
- `git diff --check`：通过；仅提示工作区现有 LF/CRLF 转换告警。
- 视觉验证：受阻。Computer Use 初始化报错 `failed to write kernel assets: 系统找不到指定的路径。 (os error 3)`，未将未执行的真实详情弹窗目视检查标记为通过。

## 实现结果

- 从预约详情进入挂号收银时，与预约列表挂号收银执行相同的固定项目约束。
- 从预约详情进入诊后收银结算时，与预约列表诊后结算保持相同的可追加项目和交付能力。
- 限制同时应用在界面和提交数据，不能通过修改前端表单值绕过数量与配送约束。
- 详情页支付方式现与列表页一致：现金默认、小程序待支付通知、微信扫码支付，不再提供付款码支付。
- 扫码支付未确认成功前不能完成结算；支付单可打印，二维码位于右下角。
