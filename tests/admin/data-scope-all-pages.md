# 运营后台业务数据范围一致性

- 日期：2026-11-04
- 状态：待回归
- 需求：列表、详情、统计统一使用用户覆盖或角色继承的数据范围；个人关联数据跨门店可见，指定门店只统计对应门店，系统范围查看全部。
- 公共资料：用户明确商品、文章、分类、轮播图等仅按菜单和功能权限访问，不添加数据范围限制。

## 核对范围

预约、患者、病历、治疗、随访、医生、门店、排班、订单、退款、交付、售后、分销、日志、通知、搜索、仪表盘和经营统计。配置页面、账号角色配置及公共资料继续由功能权限控制。

| 模块 | 本轮处理与核对 |
| --- | --- |
| 预约、患者、订单、经营报表、看板 | 复用既有统一范围；补齐退款列表、支付状态查询，个人创建关系继续生效 |
| 医生、门店、排班 | 去除只读接口中的旧角色/操作门店限制；医生列表筛选不能绕过范围；关联门店、接诊数、门店预约/收入按同一范围查询 |
| 病历、治疗、设备 | 患者可见不代表其所有跨店病历可见；列表、最新病历、治疗、佩戴汇总、履约历史和附件下载同步过滤 |
| 手工治疗建档 | 有病历归属时按原病历门店；没有任何病历关联时作为患者级记录跟随患者范围，不猜测医生当前所属门店 |
| 随访、CRM、售后 | 个人按实际跟进人/分配人/创建人等归属；无独立门店字段的患者级记录按患者范围；售后关联交付单继续校验 |
| 履约、送厂 | 列表、详情、历史、事件/资料下载复用交付范围；混合批次在查询分页前要求所有交付单可见，详情同样校验 |
| 分销 | 推广员、团队、佣金流水、总览、排行、二维码统一范围；佣金按可见原始订单重新汇总，不返回跨范围累计数 |
| 提现 | 提现没有逐单拆分记录，只有整钱包来源均可见才返回；部分可见推广员的整钱包余额返回 null，页面/导出显示“—”，不伪造为 0 |
| 日志、通知、搜索、IM | 业务日志按关联记录，个人操作日志按本人，小程序日志/通知按关联患者账号；列表与计数同步；搜索及会话复用患者/订单/预约范围 |
| 权限配置 | 专用 `/data-scope-stores` 仅返回配置用门店 ID/名称，保留原超级管理员限制，避免配置选项被业务查看范围截断 |
| 公共资料 | 商品、文章、分类、轮播图保持菜单/功能权限控制；受限门店账号验证可访问公共数据 |

查看数据范围不会自动赋予创建、修改、退款审批、提现打款等操作权限，原业务写权限规则保留。账号/角色/系统配置及人员分配选项仍按功能权限管理。
