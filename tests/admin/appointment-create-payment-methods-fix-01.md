# 新建预约付款方式与待付款通知修复记录

- 日期：2026-10-23
- 端：管理后台、后端 API、微信小程序通知链路
- 模块：预约管理 / 新建预约
- 状态：待回归

## 需求范围

- 新建预约仅提供“现金支付”和“小程序支付”。
- 默认选择现金支付；管理员确认后表示线下已实际收款，并完成预约创建。
- 小程序支付生成关联预约的待支付订单，用户可在小程序预约列表或预约详情中支付。
- 生成小程序待支付订单后触发微信订阅通知，点击进入对应预约详情。

## 约束

- 微信订阅消息只有在用户已授权相应模板且运营后台已启用并配置模板时才能实际送达。
- 通知失败不能回滚已成功创建的预约或待支付订单。

## 实施结果

- 新建预约收银弹窗仅保留“现金支付”和“小程序支付”，每次打开默认选中现金。
- 现金支付提交前保留“已实际收到款项”二次确认；订单写入支付时间并由既有结算逻辑将预约从待支付推进为待就诊。
- 小程序支付创建 `pending` 订单后关闭收银弹窗并返回预约列表；预约继续保持 `pending_payment`，用户可从小程序预约列表或预约详情发起支付。
- 管理端创建预约时延迟原“预约创建”通知，避免尚未选定支付方式就提前通知。
- 小程序待支付订单创建成功后触发 `payment_due` 订阅消息，链接为 `pages/appointment/detail?id=<预约ID>`。
- 小程序订单订阅场景加入 `payment_due` 模板；通知事件已允许在运营后台配置和启用，并复用订单状态模板字段。
- 其他页面的微信扫码、付款码、现金及小程序支付能力未修改。
