# BIND-RISK-01 动态两层分佣修复

- 日期：2026-10-22；状态：待回归；仅本缺陷实现及相关开发自测。

## 实现思路与改动点

- 新增 `hanjing-clinic-backend/distribution-relationships.js`：在绑定事务中锁定当前用户的直接下级一级关系，为这些直接下级新增或更新二级上级。依赖现有 `(child_user_id, level)` 唯一约束，不递归变更更深层关系。
- `routes/client.js`：小程序成功绑定后在同一事务内调用同步函数；佣金归属通过两条一级关系连接获取，只返回一级和二级，不再依赖可能缺失或陈旧的二级缓存记录。
- `routes/admin.js`：管理端绑定/改绑采用同一同步函数，关系写入失败随原事务回滚。
- A 后绑定 E：B 的二级关系更新为 E；C 的二级仍为 A、D 的二级仍为 B。新佣金遵守这个两层限制。
- 商品分销开关、商品一级/二级比例快照、实付金额计算逻辑不变。
- 不修改已生成的佣金，不补发历史佣金；不执行历史关系批量迁移。已有缺失/陈旧二级缓存不影响新佣金的两条一级关系查询，但既有缓存的其他展示用途未做批量修复。
- 归属读取时点仍为支付完成生成佣金时；没有把订单创建时的上级变为冻结快照。
