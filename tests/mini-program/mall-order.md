### MALL-01：订单商品总件数错误

- 现象：一个订单包含商品 A ×3、商品 B ×2，列表显示“共 2 件商品”。
- 预期：总件数应为 5。
- 实际：`itemCountLabel` 使用商品行数，结果为 2。
- 复现：模拟订单列表返回两行商品，数量分别为 3、2；执行 `loadOrders`；读取列表展示字段。
- 证据：`mp-weixin-rewrite/pages/order/index.js:135`。
- 风险：低，影响订单核对；未发现因此改变支付金额。

### MALL-02：已发货订单无法从详情申请退款

- 现象：订单状态 `shipped` 时页面的申请退款按钮不显示。
- 预期：前端对后端允许申请退款的状态提供对应入口。
- 实际：`normalizeOrder({status:'shipped'})` 的 `canRefund=false`；模板仅在该值为 true 时显示按钮。后端 `applyRefund` 明确允许 `shipped`（也允许 `processing`）。
- 复现：将订单详情响应设为已发货；执行详情归一化；检查操作标志及 WXML 条件；对照后端退款申请状态条件。
- 证据：`mp-weixin-rewrite/pages/order/detail.js:119`、`detail.wxml:87`、`hanjing-clinic-backend/refunds.js:25`。
- 风险：中，已发货用户缺少自助退款申请入口；本轮未发起真实退款，也未验收退款到账。

### MALL-03：旧请求覆盖新结果

- 现象：同一页面前后两次加载，后发请求先完成后，又被先发请求覆盖。
- 预期：最终展示较新的加载结果，不回退到较旧状态。
- 实际：在商城列表、订单列表、订单详情各复现一次，最终 ID 均为 `old` 而非 `new`。这 3 个失败断言归为同一类缺陷。
- 复现：发起 A 请求并延迟；发起 B 并返回 `new`；再完成 A 返回 `old`；读取最终页面数据。
- 证据：`mp-weixin-rewrite/pages/product/index.js:136`、`pages/order/index.js:95`、`pages/order/detail.js:124`。
- 风险：中，商品内容、订单状态和可用操作可能回退。仅证明响应乱序覆盖，不声称已发生重复扣款或跨账号泄露。

### MALL-04：鉴权失败后仍展示缓存订单

- 现象：订单列表已有数据，再次进入时接口拒绝鉴权，原订单仍可见。
- 预期：明确鉴权失效时，不继续展示私有订单数据；与普通临时网络失败区别处理。
- 实际：首次加载 1 条订单；下一次 `onShow` 模拟 HTTP 401 异常；`visibleOrders.length` 仍为 1，并未清空。
- 复现：先返回成功订单列表；将后续 `getOrders` 改为拒绝且 `statusCode=401`；执行 `onShow`；检查缓存列表。
- 证据：`mp-weixin-rewrite/pages/order/index.js:95` 的加载失败分支，在 `hasLoaded=true` 时仅解除 loading。
- 风险：中，失效会话下保留私有信息；本轮未执行真实账号切换，不能断言另一个真实账号已读取到订单。

### MALL-05：数量控件允许无效购买数量

- 现象：数量为 99 时继续点击加号变为 100。
- 预期：页面数量选择与服务端每商品最多 99 件的规则一致。
- 实际：前端允许选择 100；后端实际路由针对数量 100 返回 400，且没有进入写入阶段。
- 复现：商品详情设置数量 99，调用 `increaseQty`；用同一商品数量 100 调用隔离下单路由。
- 证据：`mp-weixin-rewrite/pages/product/detail.js:303` 与 `hanjing-clinic-backend/routes/client.js` 的 POST `/api/v1/orders` 数量校验。
- 风险：低，用户可在页面选择无法提交的数量；服务端已拒绝，未发现超限订单写入。

## 通过项与覆盖边界

- 前端：数量最小值 1、单价乘数量总额、商品分类过滤；现金/银行/门店扫码/付款码订单禁止小程序付款。
- 后端实际下单路由：0、负数、小数、100 件及合并超过 99 件均拒绝；库存不足、商品下架、缺地址、无有效归属优惠券均拒绝，模拟写入记录为空。
- 客户端伪造商品价和实付额不生效：服务端商品单价 1000 分、数量 2，结果为 2000 分而非客户端 1 分。
- 会员单件取整：101 分 ×0.95 取整为 96 分，再乘 3，结果为 288 分。
- 既有 22 项支付重试/分佣脚本通过，具体范围见 POC 报告。SQL 模拟器不验证数据库锁、唯一约束或事务回滚能力。
