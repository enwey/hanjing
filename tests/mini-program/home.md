## HOME-01：旧响应覆盖新结果

- 现象：多次进入首页引起加载交叠，后发成功请求可能被较早请求覆盖。
- 预期：展示较新的加载结果；旧失败不应覆盖已成功的新结果。
- 实际：新统计值 2 先返回，旧统计值 1 后返回，最终显示 1；另一变体旧三个请求全部失败，新请求已经成功，最终仍显示“加载首页失败”。
- 复现：延迟第一次 loadPage 的响应；执行第二次 loadPage 并返回成功；再完成第一次为旧成功/旧失败；读取 patientCountLabel、loadError。
- 证据：pages/index/index.js 的 loadPage（109 行起）；脚本两个 HOME-01 断言失败。
- 风险：中，首页统计、推荐内容及可用状态回退。实际页面逻辑隔离复现，不声称已在真机重现。

## HOME-02：局部接口失败被表现为空列表

- 现象：仅医生或门店接口失败时，对应列表为空，但首页不显示错误。
- 预期：能区分“确实没有数据”和“该模块加载失败”。
- 实际：getDoctors 或 getStores 拒绝，其余接口成功；loadError 为空、无 toast、对应列表为空。WXML 仅根据 loadError 展示统一提示，没有局部错误展示。
- 复现：分别令医生、门店 API 抛出网络错误，其余返回有效数据；执行 loadPage 并检查列表及反馈。
- 证据：pages/index/index.js:142 的 allFailed 及 150 行；pages/index/index.wxml:48 和列表条件。
- 风险：中，用户无法判断推荐医生或门店消失是故障还是无可用数据。两个失败断言归为同一缺陷。

## HOME-03：重复预约导航调用

- 现象：连续点击“立即预约”产生多个相同导航请求。
- 预期：一次未完成的预约入口跳转不重复发起。
- 实际：连续执行 goStoreSelect 三次，wx.navigateTo 调用 3 次（预期 1）。
- 复现：模拟同一页面快速三次点击，记录导航 API 调用。
- 证据：pages/index/index.js:183；首页按钮绑定 goStoreSelect。
- 风险：低，存在重复页面入栈/导航忙错误风险。本轮只确认重复调用，未实际控制微信，不能声称平台已创建三个页面或发生重复预约订单。

## HOME-04：医生头像资源不存在

- 现象：真实医生接口返回三条记录，其头像地址无法取得图片。
- 预期：接口返回的头像 URL 可返回图片；无真实头像时占位内容与数据状态应明确。
- 实际：GET 和 HEAD /static/demo/doctor-1.jpg、doctor-2.jpg、doctor-3.jpg 均返回 404，内容类型为 JSON，不是图片。
- 复现：GET 本地 /api/v1/doctors；提取头像字段；按 image-url 模块规则解析为本地 5005 地址，再 GET 三张图片。
- 证据：home-results-01.json 的真实请求结果；实际图片归一化与卡片错误回退逻辑已执行。
- 风险：低，仅确认当前本地环境，不推断线上同样缺失。卡片错误回退通过，可保留品牌占位图；未验证真机视觉。
