## 数据和版本控制

- 所有测试用户、患者、成员、姓名证件及评估数据，仅由`POST /auth/wx-login`、`PUT /user/profile`、`POST /user/family-members`、`POST /assessments/ess`等实际业务接口创建或修改。每条独立使用不同账号/号码；证件修改遵守接口校验，不直接写patients。
- 测试观察连接的SQL帮助函数仅允许SELECT/SHOW；脚本没有直接INSERT/UPDATE/DELETE/REPLACE/TRUNCATE/ALTER业务表。必要的CREATE DATABASE、标准schema初始化、USE和最终DROP测试库是环境准备/清理，不是构造目标用户状态。
- 不注入旧版账号、患者指针、会员或治疗记录；不自签管理员，也不使用seed演示数据。通过ESS实际提交创建可识别业务记录，再核对归属、迁移和保留。
- 家庭成员接口允许storeId省略，本轮按该接口实际接受的参数创建；小程序前端要求所属诊所，本轮没有通过UI填写/提交，因此这些项只判API路径，不声称页面表单或诊所创建通过。临床治疗所需有权限后台流程未执行，PAT-003整条不判通过。
- 原工作区在其他任务中变动。最终重测使用`_codex-tmp/registration-api20-source-20261106/`冻结的后端源码，未复制.env、上传或业务数据库数据；node_modules链接到现有依赖。原工作区业务文件未修改。
- [源码快照清单](artifacts/registration-login-p0-api-retest-2026-11-06/source-manifest.json)和最终JSON保存源码哈希，冻结源码运行前后sourceStable=true。测试代码与历史JSON分开保存，不覆盖旧缺陷失败记录。
