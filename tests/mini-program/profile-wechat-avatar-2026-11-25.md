## PROFILE-AVATAR-01

- 用户报告：编辑个人资料，选择微信头像后保存，出现 `Data too long for column 'avatar_url' at row 1`。
- 预期：保存成功，重新打开个人资料后显示已保存的头像。
- 修复前复现：模拟微信登录上游，经真实登录接口创建测试账号，走 multipart 文件上传及资料保存。上传响应地址带访问签名，超过 `users.avatar_url` 的 255 字符限制，资料更新返回 HTTP 500，隔离 MySQL 记录 `ER_DATA_TOO_LONG`。
- 后端 `hanjing-clinic-backend/routes/client.js` 校验私有上传文件访问权限，只保存原始路径，并由现有响应中间件签发生效的显示地址。超长地址在 SQL 执行前返回 HTTP 400。
- 小程序 `mp-weixin-rewrite/pages/profile/settings/personal-info/index.js` 仅在更换头像时提交头像字段，保存后的资料读取使用服务端返回的头像地址，再次载入编辑页时保留尚未提交的本地预览。
- 用户再次反馈后，小程序也改为从上传结果中提取文件路径再提交。隔离测试运行实际 Page 保存函数，验证带域名的完整签名上传地址被转换为短路径，真实资料接口可保存并返回签名显示地址。
- 隔离 HTTP/MySQL 自测通过。验证上传签名地址可保存、数据库仅存原始路径、只改昵称保留头像、重新打开资料可下载同一图片、无签名的私有文件不可下载、其他账号不可引用该文件以及超长外部地址返回 400。脚本为 `node tests/mini-program/profile-wechat-avatar.integration.mjs`。
- 小程序 Page 模拟自测通过。覆盖头像预览、上传失败保留待选头像和重试、成功后显示服务端地址、取消恢复头像以及只改昵称不提交头像。已有 `gender-unset.test.cjs` 2/2 通过，JavaScript 语法检查及 `git diff --check` 通过。
- 本地开发后端已重启。使用专用本地测试账号发出超长地址请求，确认运行中的服务返回修复新增的 HTTP 400 校验提示，无资料写入。管理后台开发服务可访问。
- 微信开发者工具 CLI 服务端口关闭，微信原生选择器、模拟器画面和真机操作未执行。正式环境发布和验证未执行，待独立回归。
