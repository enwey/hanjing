# 鼾声录音持续零分排查

- 状态：确认算法存在零信号质量校验缺口；用户实际录音的零分原因仍待录音指标/样本确认。未修改业务代码。
- 范围：mp-weixin-rewrite 当前录音分析、提交、结果分数读取及后端接收链路。未操作电脑界面或正式服务器。

## 已核实

- recording/index.js 在客户端将文件作为 8kHz Int16 PCM 分析，提交 client_side_analysis=true 和 analysis_result；当前提交不上传音频供服务器重新分析。
- calculateFrameDecibel 使用 30 + log10(1 + RMS/32768*9)*50 的映射，未包含设备声压校准。
- 平均值不超过38、峰值不超过55、snoreRate=0、apneaEvents=0时，评分公式各项贡献为0。
- 鼾声阈值为噪声底+8，最低42；低幅度样本可能全部低于阈值。谱特征存在也不会绕过响度门限。
- 提交只检查文件长度至少80000字节；没有检查全零/有效信号能量。全静音可以进入正常0分报告。不能将该报告视为录音采集成功的证明。
- 结果页明确保留合法 riskScore=0，不存在通过该字段强制所有分数为0的逻辑。

## 实际执行

通过 Node VM 执行当前生产源码 analyzePcmOnClient，输入10秒、8kHz、150Hz合成正弦波（不是临床鼾声样本）：

| Int16峰值振幅 | 平均/峰值（算法显示值） | 鼾声率 | 风险分数 |
|---:|---:|---:|---:|
|0|30 / 30|0|0|
|500|32 / 32|0|0|
|1000|34 / 34|0|0|
|2000|37 / 37|0|0|
|3000|40 / 40|0|3|
|8000|50 / 50|0|17|
|16000|61 / 61|0|31|

结论：并非所有输入都固定为0；低幅度/无信号容易得到0，必须区分实际采集异常和算法阈值造成的零分。合成输入不能证明真实鼾声检测准确性。
