# 家庭成员客服通知闭环

日期：2026-11-06
状态：待回归（开发接口及交互自测通过，交主任务独立复核）

## 实现

- 现有客服页接收patientId，历史读取、HTTP发送和WebSocket连接均保持同一就诊人；默认入口仍为本人。
- im-access.js统一授权：家庭成员必须同时满足患者归属和有效user_patient_links；撤销关联后不能继续访问，不能只凭患者历史user_id获得授权。本人历史档案兼容保留。
- HTTP读写和WebSocket写入在事务内重新核验授权。WebSocket推送前重新验证令牌和患者关系，授权失效关闭1008并拒绝推送。
- 连接表改为patientId对应多个连接。关闭一个不会删除其余活跃连接，旧前端连接的回调也不会覆盖新连接。
- 运营回复先持久化未读，提交后按WebSocket实际send回调统计成功；成功才已读。失败保持未读并补通知；若HTTP已读取，不反置未读、不补重复提醒。
- 推送失败不将已保存回复返回500，避免运营重试产生重复消息。主任务定时补偿覆盖提交后尚未投递的中断窗口。
- 家庭通知跳入所属就诊人的真实会话。前端展示当前就诊人；撤权后清空旧消息并停止轮询/发送。

## 数据和边界

- 隔离临时数据库仅SQL初始化系统角色/管理员；患者、家庭关联、消息、解除关联均通过真实业务API产生。查询数据库只读取验证证据，结束删除临时库。
- 微信登录由测试JWT替代，未请求微信授权。使用真实HTTP/WS网络，并对服务端WS send注入传输失败；不以伪造业务数据库状态制造失败。
- UI使用独立headless Chrome和生产WXSS，未控制用户浏览器；不是微信原生渲染或真机验收。
