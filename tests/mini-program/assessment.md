## 缺陷详情

### ASMT-01：退出登录后评估记录残留，迟到响应及 ESS 401 刷新仍保留旧数据

- 状态：回归通过（隔离模块/调用层，非真机验收）；风险：高。
- 现象/实际：退出后 records 仍有 1 条；迟到响应仍写入 1 条；ESS 结果在 401 后 resultDetail 仍为旧报告。列表模板优先按 records.length 展示，不受 isLoggedIn 限制。
- 前置条件与复现步骤：加载过记录后退出登录并再次显示页面；另延迟列表响应至退出后返回；ESS 结果成功加载后让刷新返回 401。
- 预期：未登录时清空账号相关内容，旧响应不再展示；无权访问的结果不继续保留。
- 证据位置：pages/assessment/index.js 的 loadPage；result/index.js 的 catch；index.wxml。
- 验证范围与限制：实际页面逻辑与模拟会话/API。未操作真实账号；跨账号可见性与数据残留风险，非已证实服务端跨账号读取。

### ASMT-02：切换评估人后，旧请求覆盖当前评估人的记录

- 状态：回归通过（隔离模块/调用层，非真机验收）；风险：中。
- 现象/实际：selectedMemberId 为 2，records 最终却是成员 1 数据。
- 前置条件与复现步骤：延迟成员 1 请求，切换到成员 2 并先返回成功，再返回成员 1 数据。
- 预期：列表记录始终属于当前选定评估人。
- 证据位置：pages/assessment/index.js 的 onMemberChange。
- 验证范围与限制：模拟两个自有家庭成员及延迟响应。

### ASMT-03：离线报告同步失败阻断在线历史记录加载

- 状态：回归通过（隔离模块/调用层，非真机验收）；风险：中。
- 现象/实际：getAssessments 调用次数为 0；页面提前进入错误处理，已有在线数据未请求。
- 前置条件与复现步骤：设置 syncPendingSnoreRecordings 拒绝，而 getAssessments 正常，进入评估页。
- 预期：离线同步失败时仍可查看已有在线评估记录。
- 证据位置：pages/assessment/index.js 的 loadPage。
- 验证范围与限制：模拟同步单独失败；未修改真实离线记录。

### ASMT-04：请求恢复成功后仍显示旧错误

- 状态：回归通过（隔离模块/调用层，非真机验收）；风险：低。
- 现象/实际：loadError 保留 offline；模板在 records 为空时显示旧错误。
- 前置条件与复现步骤：完成首次加载，切换成员时返回错误，再次显示页面，返回成功的空列表。
- 预期：成功后清除旧 loadError，展示正确空状态。
- 证据位置：pages/assessment/index.js 的 loadPage/onMemberChange。
- 验证范围与限制：模拟 API 与模板分支核查。

### ASMT-05：无 ID 的 ESS 结果页读取其他账号遗留缓存

- 状态：回归通过（隔离模块/调用层，非真机验收）；风险：高。
- 现象/实际：页面直接展示 A 报告；该缓存键也不在 session-store 的账号缓存清理/归档列表中。
- 前置条件与复现步骤：缓存 A 的 last_ess_assessment_result；模拟当前账号 B；以无 id 参数打开 ESS 结果页。
- 预期：仅显示当前账号有权访问的报告，不能直接展示 A 的缓存。
- 证据位置：pages/assessment/result/index.js 的 loadPage；questionnaire/index.js 缓存写入；stores/session-store.js ACCOUNT_CACHE_KEYS。
- 验证范围与限制：无 id 路由回退路径隔离复现；正常带有效 id 的服务端读取不由此证明越权。

### ASMT-06：ESS 保存成功但跳转失败后，页面一直处于提交中

- 现象/实际：redirectTo 没有 fail 回调；isSubmitting 一直为 true，再提交被拦截。
- 前置条件与复现步骤：填写完整答案并返回保存成功；对 redirectTo 模拟失败。
- 预期：显示跳转失败或可恢复状态，不永久锁住当前页面。
- 证据位置：pages/assessment/questionnaire/index.js 的 submitQuestionnaire。
- 验证范围与限制：模拟导航失败；真实页面栈未验证。

### ASMT-07：退出录音页未停止录音，迟到 stop 回调仍触发提交

- 状态：回归通过（隔离模块/调用层，非真机验收）；风险：高。
- 现象/实际：onUnload 对 recorder.stop 调用 0 次；卸载后的 stop 回调仍调用 submitRecording 1 次。
- 前置条件与复现步骤：注册录音回调并设置录音中，调用 onUnload；随后模拟 recorder onStop。
- 预期：离开已卸载页面时终止所属录音，旧页面回调不能继续提交或更新。
- 证据位置：pages/assessment/recording/index.js 的 onUnload/bindRecorderEvents。
- 验证范围与限制：录音管理器模拟复现；未实际采集麦克风。真实系统是否停止录音受平台影响，未断言实际持续采音时长。
