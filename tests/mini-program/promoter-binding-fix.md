## 修复思路与改动点

1. BIND-01：app.js 对 scene 解码异常做隔离，异常 scene 不再中断启动；仍可使用普通 query 邀请码。
2. BIND-02：app.js 和 session-store.js 清理邀请码前，对比本次邀请码与登录令牌，旧请求不能清理不同邀请码或不同登录令牌下的缓存。无明确终态的响应不再默认视为 bound。后端明确拒绝停用身份/循环关系时按终态清理，临时错误保留重试依据。
3. BIND-03：app.js 按令牌与邀请码复用进行中的绑定 Promise，避免 onLaunch/onShow 重复发起同码请求；请求结束后释放。此去重范围是 app 生命周期入口，不宣称所有业务调用共享去重。
4. BIND-04：client.js 绑定时只接受 active/pending 身份，只允许 pending → active；资料汇总中的自动激活也限定为 pending，保留首次邀请激活流程，不重新激活停用身份。
5. BIND-05：client.js 在同一事务连接中锁定推广身份、被邀请用户及祖先用户，遍历一级父链，拒绝回到被邀请用户或重复祖先的关系；校验完成才写入一级/二级关系。并发锁冲突如触发死锁，由数据库事务回滚，返回失败并保留前端重试缓存。未迁移或自动清理历史关系。
