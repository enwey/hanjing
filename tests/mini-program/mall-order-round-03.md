## MALL-10：创建订单结果不明确后，重试再次发送创建请求

- 风险：中；状态：回归通过（隔离模块）。第 7 轮独立重跑原两个异步恢复失败场景均通过，防重与账号隔离保持通过；真实交易未验证。此前失败及开发自测保留为历史。
- 现象：首次创建发生响应丢失，或返回内容缺少订单 ID 时，用户重试会再次创建。
- 预期：前一次是否成功尚不明确时，同一笔购买重试不应直接形成另一笔订单。
- 实际：注入“提交成功但响应丢失”后连续提交两次，模拟提交计数为 2；成功响应缺 ID 场景，创建 API 调用也为 2。
- 复现：商品详情配置有效商品、数量和地址；模拟第一次 createOrder 已提交但抛出网络错误；等待提交结束；不改购买信息再次提交；检查创建调用次数。另一变体将响应设为 data 空对象后重试。
- 证据：新增脚本前两个断言；商品详情 submitOrder 只有取得有效 ID 才记录已有订单，失败后解除提交锁；后端创建路由每次生成新订单号并执行插入。
- 影响：存在重复订单及额外库存占用风险；未动态验证真实数据库重复订单，未证明重复扣款。“服务端已提交”是本轮故障注入条件，实际确认的是前端再次发送创建请求。
- 与 POC-02 区别：原问题是已取得订单 ID 后取消支付重试；本项是尚未取得可用 ID 的不确定结果。

## MALL-11：订单详情退出/切换账号后，旧支付请求仍调用支付

- 风险：中；状态：回归通过（隔离模块）。本轮验证支付参数、支付回调、确认响应各阶段的会话变化；真实支付及真机未验收。
- 现象：订单详情开始付款，等待支付参数期间退出或切换账号，旧响应回来后仍调用微信支付。
- 预期：登录会话已退出或切换，旧会话的待处理付款不再启动。
- 实际：新登录与退出登录两个场景均记录到旧订单 wx.requestPayment 调用 1 次，预期 0 次。
- 复现：加载可支付订单；调用 onPayOrder 并延迟 payOrder 响应；通过实际 session store 切换登录令牌或清空令牌；返回旧支付参数；检查支付调用记录。
- 证据：新增脚本 new-login/logout 断言；订单详情 onPayOrder 在 await 后检查页面卸载，但未检查登录会话变化。
- 影响：旧账号付款流程在新会话或退出状态下继续启动。本轮只证明调用发生；未使用真实账号、未证明真实微信弹窗、越权扣款或资金损失。后端支付路由仍在初始请求时校验订单归属。
- 与 MALL-07 区别：本项保持页面未卸载，只改变会话；原问题是卸载页面后的迟到响应。
