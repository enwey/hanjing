# 持续鼾声检测与自适应底噪门限缺陷修复记录

- 状态：待回归
- 范围：`mp-weixin-rewrite/pages/assessment/recording/index.js` 中 `analyzePcmOnClient` 算法逻辑，解决四项关联缺陷：
  1. 播放持续鼾声时底噪门限虚高导致占比过低（11%）；
  2. 录制纯室内平稳环境音（40~44dB 无鼾声）时因门限过低导致底噪被误判为鼾声（72%）；
  3. **真实/鼻腔鼾声过零率偏高被 toneScore 一票否决清零，导致鼾声占比始终为 0% 且连带导致呼吸暂停事件清零为 0**；
  4. **模拟呼吸暂停两次超过 10 秒但结果依然显示暂停次数为 0 的 Bug**。

## 1. 根因剖析与机制缺陷
1. **鼾声占比始终为 0% 与呼吸暂停次数始终为 0 的联动根因**：
   - **鼻腔鼾声高频气流过零率被误杀**：鼻腔呼吸与鼻鼾（气流通过狭窄鼻腔、鼻甲摩擦）具有丰富的湍流与宽带谐波（过零率 ZCR 通常在 760~1200 之间）。旧代码在 `calculateSnoreToneScore` 中将 `ZCR > 760` 直接判定为 0 分，且在主流程中使用了 `toneScore === 0 ? 0 : ...` 硬截断，导致鼻鼾声即使具有强烈的 200~400Hz 鼾声共振峰，`snoreScore` 也被一票否决为 0；
   - **打鼾帧不足两帧一票否决呼吸暂停**：在 `analyzePcmOnClient` 末端存在硬兜底 `if (snoreFrames < 2) return { ... snoreRate: 0, apneaEvents: 0 }`。因为上述过零率误杀导致 `snoreFrames` 为 0，即使中途准确识别了 2 次 10 秒呼吸暂停，也被该硬兜底全部重置为 0；
   - **静音门槛静音区间与底噪不匹配**：旧静音门槛 `clampNumber(snoreThreshold - 3, 38, 43)` 将上限锁死在 43dB。当测试环境处于 42~44dB 正常室内底噪时，暂停期间环境音即达 42~43dB，微小浮动即超出静音门槛导致静音累计失败；
   - **离散 1 秒整块离散截断**：人脑掐表计数 10 秒在微信 1 秒分块离散采样中，若掐头去尾易只有 7 个完整静音块，旧逻辑要求连续 8 块导致极易差 1 秒无法达标。

2. **纯环境音 72% 误报原因**：
   - 室内平稳环境音（40~44dB）缺乏动态起伏硬门禁，且高频气流过零率（ZC > 1600）在旧公式中获得了 0.2 底分，未被彻底区隔。

## 2. 优化方案实施
1. **平滑鼻鼾声学与频域融合评分**：
   - `calculateSnoreToneScore` 梯级调整：
     - `60 <= ZCR <= 600`：1.0 分（纯正咽喉鼾声振动）；
     - `40 <= ZCR <= 1200`：0.7 分（鼻腔摩擦鼾声与宽带湍流）；
     - `30 <= ZCR <= 1600`：0.4 分；
     - `> 1600`：0.15 分（纯高频白噪/随机杂音）；
   - 移除 `toneScore === 0 ? 0` 的一票否决，采用加权融合 `clampNumber(toneScore * 0.35 + spectralScore * 0.65, 0.05, 1)`，使 Goertzel 频域共振峰在鼻鼾识别中充分发挥效力；
2. **自适应静音门槛与离散容差**：
   - `quietThreshold = Math.min(snoreThreshold - 2, Math.max(noiseFloor + 2, 40))`，动态适应各种房间底噪（36~46dB），确保暂停期落入底噪区间能稳定判定为静音；
   - 判定门限由 8 秒放宽至 `quietFrames >= 7`，完美覆盖 7~10 秒物理停顿与采样离散对齐误差；
   - 保留 2 秒平滑复苏窗口与录音结束时处于暂停态的自动计数；
3. **平稳环境噪音硬门禁（Flat Ambient Noise Gate）**：
   - 整段音频动态起伏不足 5dB 或标准差极小的纯环境平稳白噪，直接判定 `snoreRate: 0, riskScore: 0`。
