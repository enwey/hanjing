## HOME-05：游客档案入口重复导航且跳转失败无反馈

- 状态：回归通过（调用层）；风险：低。真机页面栈未验收。
- 现象：未登录点击“我的档案”未受到普通首页入口的导航锁保护。
- 预期：一次跳转完成前，连续点击只产生一次登录导航；打开失败时有可感知反馈。
- 实际：连续调用 3 次产生 3 次登录 navigateTo；先点预约再点档案产生 2 次并行导航；登录导航没有 fail 回调，模拟失败无 toast。
- 复现：使用未登录会话进入首页，连续点击“我的档案”；另一场景先点击“立即预约”再点击“我的档案”；另模拟 navigateTo 失败，观察调用记录和反馈。
- 证据：pages/index/index.js 的 goMedicalRecords 直接调用 common/utils/navigation.js 的 openLogin；home-round-02.cjs 三项 HOME-05 断言失败。
- 影响：重复跳转请求、导航竞争或失败后无反馈；是否实际堆叠多个微信页面尚未真机验证，不作既成事实。

## HOME-06：首页加载失败后无法原地发起重试

- 状态：回归通过（逻辑/模板绑定）；风险：低。实际视觉和触摸验证受阻。
- 现象：显示“加载首页失败”或“加载失败，请稍后重试”，但当前页面无相应重试动作。
- 预期：网络恢复后，用户能够在当前首页主动重新加载失败的数据。
- 实际：错误文本无点击事件；页面其他点击均导航离开；enablePullDownRefresh=false，且无 onPullDownRefresh。重新显示首页可恢复，但停留首页没有可用重试入口。
- 复现：让首页三个 API 拒绝，确认错误提示；恢复网络后保持首页，尝试点击提示或下拉刷新。隔离执行错误场景，结合全部模板点击绑定和页面配置核查。
- 证据：index.js 的 loadPage/onShow、index.wxml 错误区及绑定、index.json 下拉配置；对应断言失败。
- 影响：网络短暂异常后需离开再返回才能重试，错误提示所述“重试”缺少当前页面操作入口。

## HOME-07：加载中与成功空列表缺少可区分的状态提示

- 状态：回归通过（逻辑/模板条件）；风险：低。实际视觉验证受阻。
- 现象：推荐医生/门店在初次请求等待中以及成功返回空数组时，均只有栏目标题而无状态说明。
- 预期：能区分仍在加载与确实没有可展示记录。
- 实际：页面 loading 字段在 WXML 中未被使用；没有加载组件或空列表条件/文案；成功空数组时 loadError 为空、两个列表为空。请求模块也未调用全局 showLoading。
- 复现：延迟首页医生请求，检查 loading=true 时模板绑定；再让医生和门店均成功返回 []，检查栏目无条目、无错误与无空状态。
- 证据：index.wxml、index.js、api/request.js；两个 HOME-07 模板断言失败，空数据逻辑用例通过。
- 影响：弱网或无数据时无法判断页面是否仍在工作。已确认状态渲染逻辑缺失，但不宣称验证了真机像素布局。
