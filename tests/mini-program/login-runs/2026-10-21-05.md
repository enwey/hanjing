## BUG-13：缓存归档写入失败导致无法退出登录

- 风险等级：高；状态：待修复；关联：RISK-02 修复后的异常边界。
- 现象：退出依赖缓存归档写入成功；写入失败时认证信息未被清除。
- 复现步骤：
  1. 建立有效密码登录态，存储一条有归属的待上传录音。
  2. 仅在写入 `account_cache_archive` 时注入同步存储异常，模拟存储写入失败；其他读写正常。
  3. 调用实际 `sessionStore.logout()`。
  4. 捕获异常后检查实际会话模块的 `isLoggedIn()`。
- 预期：明确退出后不再保持有效登录态；不能因为非认证缓存归档异常而仍然保持登录。
- 实际：归档异常直接向上传播，`isLoggedIn()` 为 true；令牌清理步骤未执行。
- 证据：`REG5 archive write failure must not leave explicitly logged-out session active` 失败，断言 `true !== false`。
- 位置：`stores/session-store.js` 的 `clearLoginState → switchAccount → switchAccountCache`。设置页确认退出后直接调用该 logout 方法，本轮已核对该调用路径。
- 影响边界：实际模块隔离复现，不是猜测；未填满真实设备存储、未使用真实账号或证明后端越权。不声称页面已经显示“退出成功”。
- 其他存储边界：相同归档错误发生在切换账号登录时，原会话和待上传数据仍保留，该测试通过；到期后重启并 A→B→A 的归属和恢复测试也通过。
