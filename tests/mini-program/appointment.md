## APT-01：列表支付入口不可用

- 复现：预约列表存在 pending_payment 记录 → 执行该记录的主操作。
- 预期：调用已导出的预约支付 API 并继续支付流程。
- 实际：提示 `api.payAppointment is not a function`；支付接口请求次数为 0。预约 API 只导出 payAppointmentDeposit，api/index.js 聚合模块中未找到 payAppointment。
- 风险：高，预约列表付款入口阻断；详情页使用另一函数，本条不宣称所有支付入口均失效。
- 位置：pages/appointment/booking/index.js 的 handlePrimaryAction；api/modules/appointment-api.js。
- 状态：回归通过（隔离模块）。

## APT-02：日期与时段错配

- 复现：先请求日期 A → 立即请求日期 B → B 先返回 → A 后返回。
- 预期：当前日期 B 只能展示 B 的排班时段。
- 实际：selectedDate 仍为 B，但 timeSlotSections 被 A 覆盖。继续点选会将日期 B 与 A 的 scheduleId 一起写入草稿。
- 风险：中，用户选错显示时段或被后端拒绝；后端有日期/排班一致性检查，未认定已发生错误数据库预约。
- 位置：pages/appointment/time-select.js 的 loadSchedulesForDate、handleTimeSlotTap。
- 状态：回归通过（隔离模块）。

## APT-03：刷新后就诊人被重置

- 复现：本人 id=1、家人 id=2 → 确认页选择家人 → 返回该页触发 onShow/loadPage（例如进入添加家人页后不新增而返回）。
- 预期：仍选中已选择的家人，除非用户明确更换或档案不再可用。
- 实际：memberIndex 从 1 重置为 0，当前患者 id 从 2 变成 1；submitAppointment 将使用重置后的患者 ID。
- 风险：高，容易为错误就诊人提交预约；本轮没有提交真实患者资料。
- 位置：pages/appointment/confirm.js 的 loadPage，默认选择 selfIndex，未保留当前选择。
- 状态：回归通过（隔离模块）。

## APT-04：创建成功后的重复提交窗口

- 复现一：返回 pending_payment → 支付确认弹窗尚未处理 → 检查 isSubmitting。
- 实际一：isSubmitting 已变为 false，创建成功到支付完成之间未持续锁定。
- 复现二：返回 pending → 延迟订阅回调及跳转 → 再次执行提交。
- 实际二：createAppointment 调用 2 次。创建请求仍在进行中的普通连点检查通过，问题在创建完成、离页之前。
- 预期：已有创建结果后，不应再次创建同一份预约。
- 风险：中，重复占用名额或生成多个待支付记录。后端创建路由检查时段容量，但本轮未进行真实重复创建验证；弹窗遮罩是否阻止手势需真机确认。
- 位置：pages/appointment/confirm.js 的 submitAppointment、finally 及异步订阅/支付回调。
- 状态：回归通过（隔离模块）。

## APT-05：明确拒绝原因不可见

- 复现：创建接口返回“该时间段预约人数已满，请选择其他时间段”。
- 预期：用户能看到名额已满等实际原因，知道当前选择不能继续。
- 实际：只显示“预约失败，请重试”，原错误原因丢失。
- 风险：中，用户可能反复提交不可用时段；同类患者档案/评估记录拒绝也进入该通用提示分支。
- 位置：pages/appointment/confirm.js 的 submitAppointment catch。
- 状态：回归通过（隔离模块）。

## APT-06：退出后的预约数据回填

- 复现：登录态发起 loadPage，预约列表响应延迟 → 切为未登录并再次 loadPage，列表已清空 → 原请求返回。
- 预期：退出后的页面不得再显示上个账号的预约记录。
- 实际：isLoggedIn=false，但 upcomingAppointments 又出现旧账号记录，测试长度为 1 而非 0。WXML 列表区域未按登录态额外隔离，仅根据 loading/loadError/当前标签渲染。
- 风险：高，姓名、就诊日期等信息可能在退出后的页面继续显示；这是前端残留，不等于服务端越权读取。
- 位置：pages/appointment/booking/index.js 的 loadPage；booking/index.wxml 的 apt-list。
- 状态：回归通过（隔离模块）。

## APT-07：改约排班与时段错配

- 复现：选择排班 A 发起时段请求 → 选择排班 B → B 响应先返回 → A 响应后返回。
- 预期：选中 B 时仅显示 B 的时段。
- 实际：selectedScheduleId=B，但 timeSlots[0].id=Aslot。与新建预约日期错配是不同页面的独立实现。
- 风险：中，错误时段展示与提交被拒绝；不宣称后端已接受错误改约。
- 位置：pages/appointment/reschedule.js 的 selectSchedule。
- 状态：回归通过（隔离模块）。
