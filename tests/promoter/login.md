## 【逐项测试发现】

### PROM-LOGIN-01 登录接口无失败次数限制或节流

- 当前状态：回归通过
- 风险等级：高
- 现象：同一来源对不存在手机号连续发送 12 次错误登录，12 次均返回相同 404；代码范围未检出登录限流、失败计数、锁定或验证码机制。
- 复现步骤：启动推广端；连续 12 次向 `/api/promoter/login` 提交同一手机号和错误密码；观察响应。
- 预期：达到阈值后出现限流、延迟、临时锁定或额外人机校验。
- 实际：12/12 均返回 404，无限流响应。
- 潜在缺陷 / 风险：可被自动化撞库或暴力猜测；结合账号枚举会提高攻击效率。
- 证据：`hanjing-clinic-backend/routes/promoter.js` 登录路由；本地 HTTP 连续请求结果。
- 未验证项：未进行高并发或长时间攻击测试，避免对环境造成压力。
- 本轮回归结果：当前源码独立路由实例连续请求时，第 1～5 次进入业务处理，第 6 次返回 429，响应包含 `Retry-After: 900`；原“12 次均未限流”路径在本轮范围内不再成立。

### PROM-LOGIN-02 错误响应可枚举推广员账号状态

- 当前状态：验证受阻（此前修复状态保持待回归）
- 风险等级：中
- 现象：不同账号状态返回不同状态码和文案。
- 复现步骤：使用格式合法但未绑定的手机号调用登录接口，观察返回；对照路由中的其余账号状态分支。
- 预期：对外失败响应不帮助未授权者判断手机号是否注册、停用或已设置密码。
- 实际：未绑定手机号实测返回 404“该手机号未绑定推广员账号”；源码对停用、未设密码、密码错误也分别返回不同文案。
- 潜在缺陷 / 风险：可批量筛选有效手机号并定向撞库，泄露账号运营状态。
- 证据：`hanjing-clinic-backend/routes/promoter.js:182` 附近；本地 HTTP 返回。
- 未验证项：无授权账号，未实际请求其他账号状态。
- 本轮回归结果：隔离检查确认当前源码仅保留统一 401 公共认证错误并执行假哈希路径；但一次性新进程连接数据库时返回数据库鉴权错误，无法到达认证分支。运行中 3002 代理仍由旧后端提供服务，实测继续返回旧 404，不能用作新代码失败结论，也不能据此标记通过。

### PROM-LOGIN-03 登录提交期间无重复提交保护

- 当前状态：回归通过（隔离/构建范围）
- 风险等级：中
- 现象：`handleLogin` 发起异步请求期间没有提交中状态，按钮没有 `loading` 或 `disabled` 绑定。
- 复现步骤：填写合法格式数据，在响应前连续点击“立即登录”或重复按回车。
- 预期：首次提交后按钮加载并禁用，只保留一个在途请求。
- 实际：源码不存在互斥状态，每次有效 submit 都会调用接口。
- 潜在缺陷 / 风险：重复请求、重复提示和导航竞争，也会放大接口压力。
- 证据：`hanjing-promoter-portal/src/views/login/index.vue:22-32,78`。
- 未验证项：浏览器内核失败，未抓取真实网络面板中的重复请求。
- 本轮回归结果：独立检查确认入口互斥、请求前置位、按钮 loading/disabled 绑定及 `finally` 恢复全部存在；生产构建通过。真实浏览器连击仍未验收。

### PROM-LOGIN-04 窄屏登录卡片被裁切

- 当前状态：回归通过（样式约束范围）
- 风险等级：中
- 现象：卡片 `width: 400px` 且左右 padding 各 40px，默认 content-box 总宽 480px；父容器 `overflow: hidden`，没有 `max-width`、`box-sizing` 或移动端媒体查询。
- 复现步骤：在宽度小于 480px 的视口打开 `/login`，观察卡片边缘和内容。
- 预期：卡片适配窄屏，内容完整可见。
- 实际：按确定性样式计算，卡片超过视口并被裁切。
- 潜在缺陷 / 风险：手机、小窗口或分屏用户可能看不到完整表单和错误提示。
- 证据：`hanjing-promoter-portal/src/views/login/index.vue` 的 `.login-wrapper`、`.login-card`。
- 未验证项：未完成多尺寸视觉截图。
- 本轮回归结果：独立检查确认卡片使用 `box-sizing: border-box`、`max-width: calc(100vw - 32px)` 且存在 480px 媒体规则；生产构建通过。320～480px 实际截图仍未验收。

### PROM-LOGIN-05 已登录用户仍可访问登录页

- 当前状态：回归通过（路由逻辑范围）
- 风险等级：低
- 现象：`/login` 标记 public，导航守卫对 public 直接放行，未判断已有 Token。
- 预期：已有有效登录态访问登录页时进入工作台，避免重复登录和覆盖会话。
- 实际：静态逻辑会继续展示登录页。
- 风险 / 观察项：用户可能误以为会话失效并重复提交其他账号。
- 证据：`hanjing-promoter-portal/src/router/index.ts:9-12,61-70`。
- 本轮回归结果：独立检查确认路由守卫读取 Token，并在目标为 login 且存在 Token 时跳转 dashboard；生产构建通过。真实有效、过期、伪造 Token 的浏览器状态流转仍未验收。
