# 交付管理：取模到工厂交付

入口：运营后台 → 交付管理（`/fulfillment`）。收费分配技师后仍沿用现有交付单，不需要另建患者交付单。

## 操作顺序

1. **患者交付 → 取模**：核对只读医生处方与设备参数，填写口模编号、存放位置、取模日期和方式、实际测量参数、计划每日佩戴时长与时段、适应期要求、设备规格 / 制作要求。参数由医生或技师确定，系统不推断医疗值。
2. 可暂存草稿。上传 JPG、PNG、PDF、STL、PLY 附件，单文件上限 5MB，勾选本次送厂需要的附件。只有“确认取模完成”后才进入待送厂。
3. **送厂批次 → 汇总口模 / 新建批次**：默认显示上海时区当天完成的取模日期；可以改日期或选“全部待送厂（含往日）”。勾选口模并填写工厂名称，生成待寄批次。此时只是占用口模，尚未寄出。
4. 核对制作清单和实物，填写快递信息并勾选确认后寄出。批次内交付单一起更新，寄件人及寄出时间自动记录。
5. 制作清单可导出 CSV；附件在批次内单独下载并随清单发送。系统不自动给工厂发邮件或传输患者资料，也不直接调用快递下单。
6. 运营人员根据工厂反馈，逐件登记签收、制作或异常；异常处理后可恢复制作。需要重新取模时，填写原因，旧批次明细保留快照，新口模使用新编号并重新加入批次。
7. 设备回店后逐件登记编号、存放位置和验收备注。只更新当前件，不会让整批同时变为已回货。验收不通过先登记工厂异常。
8. 回货验收后继续“通知试戴 → 完成试戴”。售后仍为独立页面。

## 防错与权限

- 待寄批次可取消，口模退回待送厂；寄出后不可取消或覆盖制作快照。
- 取模草稿有版本检查；并发加入批次、重复寄出、重复验收、倒退流程会被拒绝。
- 送厂快照保留当时的处方、相关设备参数、取模参数、佩戴要求、附件清单和制作要求。后续改病历不会覆盖已寄出的资料。
- 工厂清单使用患者档案号进行对应，不导出手机号、身份证、完整既往史或整份病历。
- 查看使用 `order:view`，操作使用 `order:edit`，并核对账号分配的门店 / 患者范围。批次涉及无权访问的患者时，不能读取或操作整批。
- 文件必须登录且有当前患者访问权限才能下载，统一以附件形式下载。

## 数据与部署

新增 `fulfillment_mold_profiles`、`fulfillment_factory_batches`、`fulfillment_factory_items`、`fulfillment_mold_files` 四张表，服务启动时幂等创建，不初始化测试业务数据。已有口模编号、寄件记录、收货记录和事件日志继续保留。

回归测试：后端目录执行 `node --test tests/fulfillment-clinical.integration.test.js`。测试创建独立临时数据库并在结束后删除，不修改业务库。可设置 `DELIVERY_BROWSER_TEST=1`、`PLAYWRIGHT_MODULE` 开启浏览器端到端测试，需运营前端运行在本地 3000 端口；所有测试 API 请求转发至隔离测试服务。
