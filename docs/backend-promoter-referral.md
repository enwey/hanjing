# 后台推广员与预约推荐分佣

## 使用入口

- 运营后台「推广员管理」：/promoter。支持创建独立登录账号、下载预约小程序码、重置密码、启停账号；来源筛选区分后台与小程序推广员。
- 运营后台「商品管理」：/products，编辑商品的「分销推广」区域。原两级比例不变，另外开启后台推荐并设置 X、Y。
- 推广后台：使用运营创建的账号登录；概览下载推广码，我的患者查看推荐预约，我的团队查看关系，我的佣金查看 X/Y/层级流水，我的提现申请银行卡提现。
- 小程序：使用 mp-weixin-rewrite。扫码进入首页，在有效期内创建预约，将来源锁定到该预约；运营预约列表/详情显示推荐人。
- 收银必须关联该预约，才能取得此次推荐来源。普通商城订单不凭缓存推广码自动发 X/Y。

## 规则

1. 后台账号不创建虚拟小程序用户，不共用 users.password_hash。相同手机号也不会自动合并身份。小程序推广员不能登录推广后台。
2. 最近一次有效格式扫码保留 7 天；预约创建后再次扫码不改写旧预约。停用/无效推广码会拒绝当前预约提交并清除该次缓存，用户可重新提交或重新扫码，不会自动静默更换推荐人。
3. 收款完成后判定是否有上级。订单包含已开启后台推荐的商品才属于符合条件的成单；X/Y 只计算这些商品，不按整个订单金额计算。
4. 没有上级：生成 X 佣金并绑定后台推广员。同一商品不再叠加给该推广员的一级佣金；其他普通分销商品仍按配置处理。X=0 仍可绑定。
5. 已有上级：生成 Y 佣金，绝不改绑；原上级仍按原两级比例计佣。推荐人不能因为 Y 获得后续层级佣金。如果推荐人原本已经是上级，原有关系权益不会被删除。
6. 每次预约只产生一次 X/Y 成单奖励，后续同预约订单走普通层级佣金。不同新预约可产生新的一次推荐奖励。
7. 商品价格、分销开关与比例以订单快照为准；支付重试不读现价。优惠按行金额占比分摊实付分，余数稳定分配；佣金逐行向下取整到分。全免单不发佣、不绑关系。
8. 后台推广员作为独立父节点，没有自身上级；其下级小程序推广员继续发展用户时，可取得二级佣金。
9. 佣金先冻结，沿用订单完成及系统结算天数规则。提现进入现有运营审核/实际银行转账登记链路，不自动向银行卡付款。
10. 全额退款冲销 X/Y 和层级佣金，关系保留；已提现再退款形成需抵扣的负余额。沿用当前仅支持全额退款的限制，未新增部分退款功能。

## 数据结构与部署

- distributors：source_type 区分 mini/backend；后台记录 user_id 为空，另存联系方式、创建管理员。
- promoter_accounts：独立登录名、密码哈希、会话版本；重置/修改密码、启停后旧会话失效。
- promoter_codes：随机不可枚举来源码、状态、图片缓存；缓存绑定小程序 AppID 与正式/体验环境。
- distribution_relationships：parent_user_id 和 parent_distributor_id 二选一，数据库 CHECK 与外键约束；原小程序上下级不迁移改绑。
- appointments/orders：推荐人来源；orders 记录处理标记/成单模式。
- promoter_conversions：预约唯一的成单奖励占用记录，避免拆单重复拿 X/Y。
- products/order_items：后台推荐开关与 X/Y 比例及订单快照。
- distribution_orders：commission_kind 标识 tier/referral_new/referral_existing，calculation_snapshot 保留逐行实付、比例和金额。
- withdraw_records：支持 distributor_id，后台提现 user_id 为空。

部署后服务启动执行幂等增量迁移，不清理现有数据，不创建演示推广员，不给旧订单补发推荐佣金。既有推广端会话需重新登录，新入口只接受后台独立账号。

真实小程序码使用项目现有 WX_MINI_APP_ID / WX_MINI_APP_SECRET，WX_MINI_QRCODE_ENV 可选；正式环境默认 release，本地默认 trial。需要相应版本已发布/上传。无配置时账号创建仍成功，但明确提示二维码失败，可在补齐现有微信配置后重新获取。

## 验证边界

代码、真实隔离 MySQL、HTTP 接口与前端构建已做开发自测。二维码测试使用模拟微信响应，在线支付测试直接调用已验真流水处理函数，不等于微信真实扫码、真实付款或真机验收。用户要求不控制电脑，未进行浏览器/微信开发者工具视觉操作。
